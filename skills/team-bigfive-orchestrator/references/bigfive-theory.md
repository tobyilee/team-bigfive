# Team Big Five — 이론 기반과 에이전트 팀 적용

> 출처: Salas, E., Sims, D. E., & Burke, C. S. (2005). *Is there a "Big Five" in Teamwork?* Small Group Research, 36(5), 555–599. 팀 과학(Team Science) 분야에서 가장 많이 인용된 "팀워크의 빅파이브" 프레임워크.

이 문서는 이론을 에이전트 팀(`TeamCreate`/`SendMessage`/`TaskCreate`)·서브 에이전트·스킬에 어떻게 매핑하는지 정의한다. 조건부 로딩용 참조 문서이며, 메커니즘의 "왜"가 필요할 때 읽는다.

## 목차
1. 핵심 주장
2. Big Five 5대 구성요소
3. 3대 조율 메커니즘
4. 에이전트 팀 매핑 표
5. 흔한 실패 모드와 메커니즘 대응

## 1. 핵심 주장

팀 성과는 "각 구성원의 능력 합"이 아니라 **팀워크 행동의 질**에서 나온다. 좋은 팀은 5가지 팀워크 행동(Big Five)을 보이며, 이 행동들은 3가지 조율 메커니즘(공유 정신 모델·폐쇄 루프 커뮤니케이션·상호 신뢰)으로 가능해진다. 메커니즘이 없으면 5대 행동도 작동하지 않는다.

에이전트 팀에 적용하면: 더 똑똑한 에이전트를 더 많이 붙이는 것보다, **에이전트 간 조율 행동을 명시적 프로토콜로 강제**하는 것이 성과를 높인다. 이것이 본 하네스의 설계 가설이다.

## 2. Big Five 5대 구성요소

| # | 구성요소 | 정의 | 에이전트 팀에서의 의미 |
|---|---------|------|----------------------|
| 1 | **Team Leadership** (팀 리더십) | 팀원의 활동을 지시·조율, 목표와 역할 설정, 자원 배분, 동기 부여 | `team-lead`가 공유 목표를 정의하고 `TaskCreate`로 작업을 배분, 진행을 모니터링, 적응을 촉발, 최종 산출물을 종합 |
| 2 | **Mutual Performance Monitoring** (상호 성과 모니터링) | 팀원이 서로의 작업을 관찰하고 실수·이탈을 감지 | 팀원이 인접 팀원의 산출물을 SMM 기준으로 교차 검증, 불일치 발견 시 폐쇄 루프로 통보. `performance-monitor`가 전담 |
| 3 | **Backup Behavior** (백업 행동) | 과부하·실패한 팀원의 작업을 다른 팀원이 대신 수행 | 팀원이 막히거나 실패하면 유휴 팀원이 작업을 claim하거나 리더가 재할당 |
| 4 | **Adaptability** (적응성) | 변화하는 상황·새 정보에 따라 전략·역할을 조정 | 모니터링이 이탈을 감지하면 리더가 계획을 재평가하고 SMM을 갱신 (적응 체크포인트) |
| 5 | **Team Orientation** (팀 지향성) | 개인 목표보다 팀 목표를 우선, 타인의 기여를 존중·반영 | 각 팀원이 자기 서브태스크보다 공유 목표를 우선, 팀원 발견을 반영, 충돌 시 공유 목표 기준으로 판단 |

## 3. 3대 조율 메커니즘

Big Five 행동을 가능하게 하는 하부 메커니즘. 이것이 본 하네스의 차별점이다.

| 메커니즘 | 정의 | 에이전트 팀 구현 | 담당 스킬 |
|---------|------|----------------|----------|
| **Shared Mental Models** (공유 정신 모델) | 팀이 과제·역할·상호작용에 대해 공유하는 조직화된 이해 | `_workspace/SMM.md` 단일 진실 원천. 모든 팀원이 작업 단위 시작 시 읽고, 타인에게 영향 주는 결정 시 갱신 | `shared-mental-model` |
| **Closed-Loop Communication** (폐쇄 루프 커뮤니케이션) | 발신→수신 확인→발신 검증의 3단 루프로 메시지 전달 보장 | 작업 핵심 SendMessage는 ACK 필수. 수신자가 이해를 재진술, 발신자가 확인/정정 | `closed-loop-comms` |
| **Mutual Trust** (상호 신뢰) | 팀원이 서로의 역량·의도를 신뢰하여 중복 검증을 줄임 | 팀원의 검증된 산출물을 재작업하지 않고 신뢰하여 사용. 단, 모니터링으로 신뢰를 보정 | 에이전트 정의에 내재 |

## 4. 에이전트 팀 매핑 표 (요약)

```
[team-lead]  ── Team Leadership + Adaptability
    │  TaskCreate / 모니터링 / 적응 체크포인트 / 종합
    │
    ├── [contributor-*]  ── Team Orientation + Backup + 부분 Monitoring
    │       SMM 읽기/갱신, 폐쇄 루프 통신, 인접 산출물 교차 검증
    │
    └── [performance-monitor]  ── Mutual Performance Monitoring + Backup 촉발
            전 팀원 산출물 ↔ SMM 교차 검증, 이탈/정체 감지 → 리더에 보고

공유 인프라:
  _workspace/SMM.md         ← Shared Mental Model (단일 진실 원천)
  closed-loop ACK 프로토콜   ← 모든 핵심 메시지
  mutual trust 원칙          ← 검증된 산출물 재작업 금지
```

## 5. 흔한 실패 모드와 메커니즘 대응

| 에이전트 팀 실패 모드 | 원인 | 대응 메커니즘 |
|---------------------|------|--------------|
| 팀원들이 같은 용어를 다르게 해석해 산출물이 어긋남 | 공유 이해 부재 | Shared Mental Model — 용어/인터페이스를 SMM에 고정 |
| A가 B에게 핸드오프했는데 B가 못 받음/오해함 | 단방향 통신 | Closed-Loop — ACK + 이해 재진술 강제 |
| 모든 팀원이 같은 사실을 중복 검증해 낭비 | 신뢰 부재 | Mutual Trust — 검증된 산출물 재사용 |
| 한 팀원이 막혔는데 나머지가 무관하게 진행 | 백업 부재 | Backup — 유휴 팀원이 claim/리더 재할당 |
| 한 팀원의 오류가 끝까지 안 잡힘 | 모니터링 부재 | Mutual Performance Monitoring — 교차 검증 |
| 초기 계획이 틀렸는데 끝까지 밀어붙임 | 적응 부재 | Adaptability — 적응 체크포인트에서 재계획 |
| 팀원이 자기 작업만 최적화하고 전체는 어긋남 | 팀 지향성 부재 | Team Orientation — 공유 목표 우선 원칙 |
